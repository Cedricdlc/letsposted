# Moteur de découverte plateforme/niche — Design

> **Statut : validé, construction reportée.** Cédric veut attendre d'avoir un vrai lead (une vraie soumission du lead magnet) avant de commencer à construire — pas de développement spéculatif sans cas réel à traiter. Ce document capture le design déjà validé section par section le 2026-07-28, prêt à être repris tel quel (ou passé à `writing-plans`) le jour où c'est le cas.

## Contexte

Le lead magnet de Posted. (`landing/index.html`, modale "Get my priority plan") promet aujourd'hui : *"We'll send your priority launch plan within 24h. Read by hand, not generated by a bot."* — 100% manuel côté Cédric, aucune automatisation de la recherche de plateformes/conversations pertinentes.

"Le moteur" désigne la première brique à automatiser : la **découverte** (trouver les bonnes plateformes/conversations pour un produit donné), pas la génération de contenu ni l'outreach — ce sont des chantiers séparés, à traiter plus tard si celui-ci prouve sa valeur.

## Décisions validées

| Question | Réponse |
|---|---|
| Première brique à construire | Découverte de plateformes/niche (remplace le triage manuel du lead magnet) |
| Où va le résultat | Vers Cédric, pour validation avant envoi au prospect (garde la promesse "read by hand" honnête) |
| Infra | n8n — même plateforme que le pipeline `~/Desktop/Linkedin Hack` existant, réutilise le pattern scan→score→Telegram déjà prouvé |
| Sources cibles (vision long terme) | Reddit + X + LinkedIn + Facebook Groups |
| Sources v1 réelles | **LinkedIn seul pour commencer** (Approche A, voir ci-dessous) — réutilise l'actor Apify déjà configuré pour Linkedin Hack |
| Déclenchement | À la demande, par soumission du lead magnet — pas de scan continu de fond (contrairement à Linkedin Hack, chaque prospect a sa propre niche, pas de niche pré-définie à surveiller en continu) |
| **Condition de démarrage** | **Attendre un vrai lead réel avant de construire quoi que ce soit — pas de dev spéculatif** |

## Approche retenue : déploiement séquencé (Approche A)

Trois approches ont été comparées (voir historique de session) :
- **A — Retenue** : un seul pipeline n8n construit de bout en bout, branché sur LinkedIn seul au départ (actor Apify déjà prouvé). Une fois le flux validé sur de vrais cas, ajouter Reddit puis X puis évaluer Facebook Groups en dernier (le plus dur à scraper).
- B — Rejetée pour le v1 : les 4 sources en parallèle dès le départ — trop d'intégrations simultanées, rien de testable avant que tout soit prêt.
- C — Rejetée : prouver le scoring avec de la donnée collée à la main avant tout scraping réel — jugée comme une étape de plus non nécessaire vu qu'on a déjà un actor Apify qui marche.

## Flux (Section 1)

```
Prospect soumet le lead magnet (URL + "what are you building" + email)
  → Netlify Forms déclenche un webhook sortant vers n8n (nouveau hook à
    créer, même mécanisme que l'alerte email déjà branchée le 2026-07-27)
  → n8n :
    1. Récupère meta tags de l'URL (titre/description) — réutilise la
       même logique que readiness.js déjà en prod
    2. Extrait 3-5 mots-clés/niche à partir du contexte + meta (via
       Claude, comme l'ancien platform-copy.js, supprimé le 2026-07-27
       mais récupérable via git log si besoin de base de départ)
    3. Cherche sur LinkedIn via l'actor Apify existant
       (harvestapi~linkedin-post-search), avec ces mots-clés
    4. Score chaque post trouvé pour la pertinence (voir Section 3)
    5. Garde le top 3-5, met en forme un "plan prioritaire"
    6. Envoie sur Telegram à Cédric (même pattern que hack1/hack2b)
  → Cédric valide (ou modifie) sur Telegram
  → Le prospect reçoit son plan par email
```

## Format du plan et validation Telegram (Section 2)

Message Telegram type :

```
🎯 Nouveau prospect : [nom du produit détecté]
🔗 [URL soumise]
📝 Contexte : "[ce qu'il a écrit dans 'What are you building?']"

Top 3 conversations trouvées :

1. LinkedIn · [auteur] · il y a [X]
   "[extrait du post/commentaire]"
   → Pourquoi : [raison de pertinence en une phrase, générée par Claude]

2. ...
3. ...

[✅ Envoyer tel quel]  [✏️ Modifier]  [❌ Rejeter ce lead]
```

- **✅ Envoyer tel quel** : déclenche l'email au prospect avec ce plan.
- **✏️ Modifier** : Cédric répond en texte libre sur Telegram (ex: "vire le #2, ajoute une note sur son produit"), Claude reformule le plan, le renvoie pour validation finale — même mécanique que le "REWRITE" de hack2b.
- **❌ Rejeter** : rien n'est envoyé, le lead reste dans le suivi manuel normal (pas de perte silencieuse).

L'email final au prospect reprend le texte de la promesse actuelle + le plan validé, formaté proprement.

## Scoring (Section 3)

Contrairement à Linkedin Hack (score de **vélocité**, formule numérique pondérée : vélocité 40%, ratio commentaires/likes 25%, score auteur 20%, score contenu 15%), ici l'enjeu c'est la **pertinence** — jugement sémantique, pas une formule.

```
Pour chaque post/commentaire trouvé par la recherche :

1. Filtre dur, avant tout appel IA (gratuit, rapide) :
   - Plus vieux que 30 jours → écarté (opportunité probablement froide)
   - Déjà noyé sous 20+ réponses → écarté (créneau raté)

2. Claude juge, avec le contexte produit (meta scrapé + "what are you
   building") + le texte du post :
   - Score de pertinence 0-10 : cette personne exprime-t-elle un
     besoin que ce produit résout, pas juste un mot-clé qui matche ?
   - Une phrase de raison ("pourquoi c'est pertinent")
   - Un angle suggéré pour la réponse/le post

3. Sous 6/10 → écarté, n'arrive jamais jusqu'à Cédric
4. Le reste trié par score, top 3-5 gardés pour le plan
```

## Gestion des erreurs et cas limites (Section 4)

Principe directeur : **jamais de plan à moitié fabriqué pour "faire comme si"** — cohérent avec le reste du site (rien n'est jamais inventé quand la donnée manque).

```
- URL illisible/site inaccessible → même comportement qu'aujourd'hui :
  le plan part quand même, basé sur le contexte texte "What are you
  building?" seul (déjà le comportement de readiness.js actuellement)

- Aucun candidat au-dessus de 6/10 → pas de plan à moitié vide envoyé.
  Telegram arrive quand même, mais avec "Rien trouvé d'assez pertinent
  cette fois — voir manuellement ?" plutôt que de forcer 3 résultats
  faibles juste pour remplir le format

- Apify/LinkedIn timeout ou erreur → notification honnête, pas de plan
  fabriqué. Le lead reste dans le suivi manuel normal, rien de
  silencieusement perdu

- Doublon : même prospect soumet deux fois → pas de deuxième recherche
  déclenchée, juste un rappel Telegram "déjà traité le [date]"
```

## Validation (Section 5, et récap)

Deux validations distinctes dans ce design :

1. **Validation de chaque plan, au quotidien** — à chaque soumission, le plan part sur Telegram avant le prospect. Rien ne part sans passer par Cédric (✅/✏️/❌, voir Section 2).
2. **Validation du moteur lui-même, avant de le brancher en vrai** — avant de connecter le vrai webhook Netlify, tester avec 3-5 soumissions à Cédric lui-même ou des amis fondateurs, pour vérifier que le scoring sort de bons résultats et que le format Telegram est clair. Une fois convaincant, brancher le vrai webhook.

## Hors scope (explicitement, pour ce chantier)

- Génération de contenu (posts/réponses) — brique séparée, pourrait réutiliser/étendre l'ancien `platform-copy.js`
- Reddit, X, Facebook Groups — ajoutés après LinkedIn une fois le pipeline prouvé, pas au lancement
- Scan continu de fond façon Linkedin Hack — pas pertinent tant que chaque prospect a sa propre niche unique
- Outreach automatisé / envoi de messages — hors scope, jamais mentionné comme objectif de ce chantier précis
